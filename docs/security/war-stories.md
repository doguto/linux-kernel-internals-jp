# 事件簿: LinuxのセキュリティバグとCVE {#war-stories-linux-security-bugs-and-cves}

> LSM/ケーパビリティ/namespace/ptraceの領域で実際に起きた脆弱性 — 何が壊れ、なぜ壊れ、カーネルは何を学んだか

このページのバグは、カーネルの他の事件簿の多くとは信頼モデルの異なる部分に存在する。ネットワークのバグは通常、認証されていないリモートの相手から到達可能であり、ファイルシステムのバグは通常、細工したイメージをマウントできる者なら誰でも到達可能である。ここで扱うバグは通常のローカルユーザーアカウントから到達可能であり — 先にシェルを得るためのエクスプロイトチェーンは不要 — いずれも同じ結末を迎える。非特権のままであるべきプロセスがrootを得るか、決して触れられないはずのデータへの読み書きアクセスを得るのである。

この領域を特徴づけるのは、それが*どのように*起きるかである。4つのうち、KASANがファジングされた入力から見つけた古典的なメモリ安全性の欠陥は1つだけである。残る3つはもっと静かなものだ。以前の所有者の古い値を保持し続ける構造体フィールド、コピー元が変更される数行前に取られた派生コピー、まったく別のプロセスから取得されたクレデンシャルポインタ — しかもそのプロセスの権限が変わった後も信頼され続けた。4つ目は1行の算術ミスだが、それすら問題になるのは、Linuxの非特権ユーザーnamespaceモデルが通常のデスクトップユーザーにnamespaceスコープの`CAP_SYS_ADMIN`を与え、脆弱なコードがそれを想定して監査されたことがなかったからにすぎない。ケーパビリティ、クレデンシャル、namespaceこそがこのページのバグが破壊するプリミティブであり — それこそがこれらを危険にしている点でもある。`net/`のバグは通常何かをクラッシュさせるだけだが、ここでのバグは通常rootを明け渡してしまう。

個々のインシデントに入る前に、もう1つ繰り返し現れるパターンを指摘しておく価値がある。[ネットワークスタックの事件簿ページ](../net/war-stories.md)にある、公開の場で議論された修正のいくつかとは異なり、以下の修正はすべて公開リストに届く前にエンバーゴ下で非公開にレビューされた — Dirty Pipeとネストしたnamespaceのバグは`security@kernel.org`経由で、fs_contextのオーバーフローはディストリビュータ間で調整されたチャネル経由で、ptraceのバグは公開レビュー記録を残さない非公開チャネル経由で（Linusが直接適用した）。修正について実際のLKMLやlore.kernel.orgの議論スレッドが存在する場合は、以下の各ページがそれを引用する。存在しない場合 — ここではそれが例外ではなく普通である — は、起きてもいない議論をでっち上げるのではなく、ページ上でそのことを明記する。

以下の各インシデントには個別のページがある。実際のパッチに基づく根本原因分析、実在する一次資料（NVD、CISAのKEVカタログ、Exploit-DB、そして実際に存在するメーリングリストの記録）、そしてそのバグを可能にした設計判断についての非難なしの振り返りである。

## インシデント {#incidents}

公開日の新しい順（逆時系列）に並べている。

### [Dirty Pipe](war-stories/dirty-pipe.md) {#dirty-pipe}
**2022年3月 · CVE-2022-0847 · CVSS 7.8**
`buf->flags = 0;`がたった1つ欠けていたことが、無関係な2回のリファクタリングをまたいで6年間眠り続け、ファイルを*読む*ことさえできれば誰でもページキャッシュ上でそのファイルを上書きできるようにしてしまった — immutableファイル、読み取り専用のbtrfsスナップショット、読み取り専用マウントも含め、ケーパビリティは一切不要であった。CISAのKEVカタログによれば、公開から7週間以内に実際に悪用された。

### [fs_contextのレガシーパラメータのオーバーフロー](war-stories/fscontext-overflow.md) {#the-fs_context-legacy-parameter-overflow}
**2022年1月 · CVE-2022-0185 · CVSS 8.4**
和ではなく差として書かれた境界チェックが符号なし算術でアンダーフローし、非特権アカウントからそこに到達するには`unshare -Urm`だけで十分だった。あるチームは数日のうちにこれをKubernetesのpodエスケープに武器化して31,337ドルのバウンティを得た。別のディストリビューションを標的にした2つ目の独立したエクスプロイトが1週間後に続いた。

### [古いptracerクレデンシャル](war-stories/stale-ptracer-creds.md) {#stale-ptracer-credentials}
**2019年7月 · CVE-2019-13272 · CVSS 7.8**
`PTRACE_TRACEME`は、要求した子のクレデンシャルではなく*親の*クレデンシャルをトレーサのものとして記録していた。そのため非特権プロセスは自分の特権を持つ親を自分のptracerにし、その親が権限を落として攻撃者の手が届くものをexecするのを待ち、ptrace関係の当初の、まだ特権を持つ権限を保持し続けることができた。1週間以内に、テストされた20余りのディストリビューション上でpolkitの`pkexec`に対して武器化された。

### [ネストしたユーザーnamespaceのUID/GIDマッピング](war-stories/nested-userns-uid-mapping.md) {#nested-user-namespace-uidgid-mapping}
**2018年11月 · CVE-2018-18955 · CVSS 7.0**
ある性能最適化がnamespaceのIDマッピングテーブルのソート済みコピーを2つ保持していたが、変換していたのはその片方だけであった。この不整合は、2階層以上のネストかつ5つを超えるIDレンジがマッピングされている場合にしか表に現れない — そして`uidmap`パッケージのsetuidヘルパー`newuidmap`さえあれば到達可能だった。ネストしたnamespace内の非特権プロセスがホストの`/etc/shadow`を読めたのである。

## 共通する傾向 {#common-threads}

| パターン | Dirty Pipe | fs_contextのオーバーフロー | 古いptracerクレデンシャル | ネストしたusernsマッピング |
|---------|:----------:|:--------------------:|:--------------------:|:-----------------------:|
| ケーパビリティもnamespaceの小細工も一切なしで到達可能 | Yes | No | 部分的 | 部分的 |
| 悪用可能性が非特権ユーザーnamespaceの有効化に依存する | No | Yes | No | Yes |
| 根本原因が符号なし整数の算術（オーバーフロー/アンダーフロー） | No | Yes | No | No |
| 根本原因が状態変化の前から持ち越された古い値 | Yes | No | Yes | Yes |
| 自動ファザー（syzbot）が独立に最初に発見し、放置された | No | Yes | No | No |
| 公開されたエクスプロイトツールが存在する（PoCまたはMetasploitモジュール） | Yes | Yes | Yes | Yes |
| 実際の悪用が確認されている（CISA KEV） | Yes | Yes | Yes | No |
| 修正がエンバーゴ下で非公開にレビューされ、LKMLで実質的な公開議論はない | Yes | Yes | Yes | Yes |

1行目の「部分的」は、*ケーパビリティ*はチェックされないが、バグには特定の構造的前提条件が依然として必要であることを意味する — ptraceのバグでは特権を持つ親プロセス、UIDマッピングのバグでは2階層以上ネストし5つを超えるIDレンジがマッピングされたnamespaceである。Dirty Pipeはそのどれも必要としなかった例外である。2020年から2022年2月までの間にビルドされたカーネル上で、対象ファイルへの通常の読み取りアクセスがあることが前提条件のすべてであった。

古い値のパターンは、4つのうち3つを貫く最も強い共通点である。以前の占有者のフラグを保持し続ける`pipe_buffer`スロット、コピー元の追跡をやめた`kmemdup()`された配列、正しいタイミングではあるが誤ったコンテキストで誤ったプロセスから取得されたクレデンシャルポインタ — どれも、このサイトの他の場所でメモリ安全性CVEの大半を占めるバッファオーバーランやuse-after-freeではない。書かれた時点では正しかったが、周囲で変化したものに対して何も再検証しなかったために、後で黙って誤りになった状態である。これはサニタイザで捕まえるのが難しいバグクラスであり、実際それが表れている。この3つはいずれもファジングでは見つかっていない。

fs_contextのバグはほぼすべての行で例外であり、まさにその例外となっている行こそが、CVSSで4つの中で最も深刻なものにしている。古典的な符号なしアンダーフローの境界チェックであり、まさにKASANとsyzkallerが捕まえるために作られた種類のものである — そして実際syzbotは、公開の際にクレジットを得たCTFチームより6日早く独立にそれを捕まえていたが、[このサイトのネットワーク側](../net/war-stories/netfilter-xtables.md)でnetfilter x_tablesの報告が8か月間放置されたのと同じように、Androidツリーのバグトラッカー上で放置されていた。この4つのバグのいずれについても、検出がボトルネックだったことはない。ボトルネックはトリアージだった — そしてここでの非公開・エンバーゴ下の3つの公開については、後にメーリングリストを掘り返す者にほとんど何も残さなかったとしても、カーネルのセキュリティプロセスは設計どおりに機能したことを記録が示している。

4つのうち3つはCISAのKEVカタログで実環境での悪用が確認されている — ネットワークのページの6つ中1つと比べると際立って高い割合である。ローカル権限昇格のプリミティブは、すでに足がかりを持つ攻撃者にとって、リモートからのクラッシュが通常そうではないような形で直接役立つ。このページのバグがすべてまずローカルアクセスを必要とするにもかかわらずKEVへの収録率が高いのは、それがもっともらしい理由である。
